# 学内施設・備品予約貸出管理システム 要件定義書（セキュリティ監査反映版）

## 1. 概要

### 1.1 目的
紙・口頭・表計算ファイルなどで個別管理されている学内施設・備品の予約・貸出業務をWeb上で一元管理し、予約重複や確認漏れを減らす。

### 1.2 開発対象・環境
- 学内向けWebシステム。一般公開は想定しない。
- PHP / MySQL・MariaDB（XAMPP）/ HTML / CSS / JavaScript / Git / GitHub / VSCode
- 前半セット第1回〜第7回で設計・開発・テスト・発表まで行う。

## 2. 利用者・権限

### 2.1 一般利用者
一般学生、および予約のみを行う教員。

可能：ログイン、一覧・検索・詳細閲覧、予約申請、自分の予約状況確認、申請中予約のキャンセル。

不可：他利用者の予約閲覧・変更、管理機能、承認・却下、貸出・返却状態変更、自分自身の権限変更、監査ログ閲覧・変更。

### 2.2 管理担当者
学務課職員、および管理を補助する教員。

可能：一般利用者向け機能、施設・備品の登録・変更・利用停止、申請一覧、承認・却下、貸出・返却、返却期限超過確認。

### 2.3 教員
第三の権限は設けず、業務内容に応じて一般利用者または管理担当者として扱う。

### 2.4 管理担当者アカウント
初期の管理担当者アカウントは初期データまたは管理者専用の安全な方法で事前登録する。一般利用者向け処理から管理担当者権限を付与できないようにする。

## 3. MVP対象範囲

「施設・備品を探す → 予約申請 → 管理者承認 → 貸出 → 返却 → 状況確認」を正しく動作させることを優先する。

MVPに含める：ログイン・ログアウト、権限制御、施設・備品一覧、名前・分類検索、詳細、予約申請、重複防止、承認・却下、貸出・返却状態管理、自分の予約状況、申請中キャンセル、利用停止、返却期限超過表示、基本的なWebセキュリティ、重要操作の監査ログ。

## 6. 状態遷移

```text
申請中
 ├─ 管理担当者が承認 → 承認済み
 ├─ 管理担当者が却下 → 却下
 └─ 一般利用者がキャンセル → キャンセル

承認済み
 └─ 管理担当者が貸出処理 → 貸出中

貸出中
 └─ 管理担当者が返却処理 → 返却済み
```

定義されていない状態遷移はサーバ側で拒否する。

返却期限超過は独立状態ではなく、`状態=貸出中 AND 返却予定日<現在日` の場合の表示とする。

## 7. 主要データ

### 7.1 利用者
利用者ID、氏名、学籍番号または職員番号、メールアドレス、パスワードハッシュ、権限、利用状態。

### 7.2 分類
分類ID、分類名、説明。

### 7.3 施設・備品
対象ID、名称、分類ID、説明、保管場所、利用状態。

### 7.4 予約・貸出
予約ID、利用者ID、対象ID、利用開始日、返却予定日、利用目的、状態、貸出日、返却日、担当者ID、備考。

MVPでは予約と貸出・返却を1つの予約データで扱う案とする。最終的なテーブル分割は詳細設計で決定する。

### 7.5 監査ログ
ログID、実行者ID、実行日時、対象種別、対象ID、操作内容。

パスワード、セッションID、CSRFトークン、DB接続情報は記録しない。

## 8. 業務ルール

1. 予約は利用開始日〜返却予定日の日付範囲で管理し、時間単位は扱わない。
2. すべて管理担当者の手動承認とする。
3. 利用目的は必須入力とする。
4. 一般利用者のキャンセルは申請中のみ。
5. 施設・備品は物理削除せず利用停止で管理する。
6. 利用停止中の対象は新規予約不可。
7. 承認済み・貸出中予約がある対象は利用停止不可。
8. 教員専用権限は設けない。
9. 重複成立判定の対象は承認済み・貸出中。申請中同士は共存可。
10. 承認時に重複チェックを再実行する。
11. 同一利用者・同一対象・同一期間の申請中予約の多重登録は拒否する。
12. 更新前に現在状態を再確認し、想定外の状態なら更新を拒否する。
13. 成功した登録・更新は POST → Redirect → GET を基本とし、再読み込みによる二重送信を防止する。
14. 予約ID・対象IDは連番可。ただしIDを知るだけでは閲覧・変更できないよう認可を必須とする。
15. 利用者自身による権限変更は禁止する。
16. 複数DB更新を一連の処理として行う場合はトランザクションを使用し、失敗時はロールバックする。
17. クライアントから送られた利用者ID・権限・状態等の重要値をそのまま信用しない。
18. ログイン後の遷移先をリクエスト値から受け取る場合は、システム内の許可済みパスのみ認める。

## 9. システム全体の受入条件

1. 一般利用者がログイン・ログアウトできる。
2. 一覧・簡易検索・詳細から施設・備品を探せる。
3. 利用開始日・返却予定日・利用目的を指定して申請できる。
4. 同一利用者による同一内容の申請中予約の多重登録を拒否できる。
5. 管理担当者が承認・却下できる。
6. 承認時に重複を検出し二重予約を防止できる。
7. 貸出・返却の定義された状態遷移だけが実行できる。
8. 一般利用者は自分の予約だけ確認・キャンセルできる。
9. URL・POSTのID改ざんで他人のデータを閲覧・変更できない。
10. 管理担当者が施設・備品を登録・変更・利用停止できる。
11. 貸出中・承認済み予約がある対象を利用停止できない。
12. 返却期限超過を識別できる。
13. 不正入力時にDBを更新せず適切な案内を表示する。
14. PDO＋プリペアドステートメントによりSQLインジェクションを防止する。
15. `htmlspecialchars()` 等によりXSSを防止する。
16. CSRFトークン不正・欠落時は更新を拒否する。
17. ログイン前後でセッションIDが変更され、ログアウト後は再利用できない。
18. 30分無操作で再ログインが必要になる。
19. SQL・DB接続情報・スタックトレース等を利用者画面に表示しない。
20. パスワードを平文保存せず、8文字未満は拒否する。
21. ログイン失敗メッセージからアカウント存在有無を判別できない。
22. 一定回数のログイン失敗後は一時的に試行制限される。
23. DB接続情報がGit管理対象に含まれない。
24. Webアプリ用DBユーザーに不要な管理権限がない。
25. 設定・ログ・バックアップへブラウザから直接アクセスできない。
26. 重要操作が監査ログに記録され、秘密情報は記録されない。
27. POST後にブラウザ更新しても同じ処理が二重実行されない。
28. 外部URLを不正なリダイレクト先として指定できない。
29. ログアウト後にブラウザの戻るだけで認証済み情報を再利用できない。
30. `X-Content-Type-Options` とクリックジャッキング対策ヘッダーが設定されている。
31. Chrome / Edgeで主要機能が正常動作する。
32. テスト結果と簡単な操作手順が用意されている。

## 10. 対象外・将来候補

### 10.1 原本で明示された対象外
決済、メール送信、QRコード、外部カレンダー連携、リアルタイム通知。

### 10.2 第7回MVP対象外
利用回数集計画面、未返却専用一覧、教員専用第三権限、時間単位予約、自動承認、高度なAjax検索、画像アップロード、予約状況カレンダー／タイムライン。

### 10.3 将来候補
未返却専用一覧、利用回数集計、教員専用権限、時間単位予約、一部自動承認、予約空き状況カレンダー、管理担当者の重要操作前の再認証。

## 11. 詳細設計で決定する事項

1. アカウントの具体的な作成・登録運用。
2. 施設と備品を同一テーブルにするか別テーブルにするか。
3. 却下理由を必須にするか。
4. 名称・利用目的・備考等の最大文字数。
5. ログイン失敗の制限回数・制限時間。
6. 監査ログをDBテーブルにするかファイルにするか。
7. セキュリティヘッダーを共通PHPで設定するかWebサーバ設定で行うか。

| REQ-NF-014 | DB秘密情報漏えい | 設定分離、Git管理外 | Gitに秘密情報なし |
| REQ-NF-015 | 不正操作の追跡不能 | 監査ログ | 実行者・日時・対象・操作を記録 |
| REQ-NF-016 | DB侵害時の被害拡大 | DB最小権限 | 不要な管理操作ができない |
| REQ-NF-017 | 設定・ログ漏えい | Web公開領域外配置 / 直接アクセス禁止 | URL直打ちで取得不可 |
| REQ-NF-018 | クリックジャッキング / MIME誤判定 | `X-Frame-Options`、`X-Content-Type-Options` | レスポンスヘッダー確認 |
| REQ-F-009 | 同時承認による二重予約 | 承認時再チェック＋トランザクション | 同時承認でも1件のみ成立 |
| REQ-F-006/007/010 | 不正な状態遷移 | 現在状態＋権限＋操作をサーバ側確認 | 定義外遷移を拒否 |
| REQ-F-005/012 | 利用停止対象への不正予約 | 予約時に対象状態を再確認 | 利用停止IDをPOSTしても登録不可 |
| REQ-F-013 | Mass Assignment | 更新可能項目をホワイトリスト化 | 不正POST項目がDBへ反映されない |
| REQ-F-005〜013 | 二重送信 / 部分更新 | PRG、トランザクション | 二重登録・部分更新が起きない |

## 14. 最終合意事項

1. WISH-03は一覧表示をMVP必須とする。
2. WISH-04は名前・分類による簡易検索としてMVPに含める。
3. 予約は利用開始日〜返却予定日の期間指定とし、時間単位は扱わない。
4. すべての予約を管理担当者の手動承認とする。
5. 学生によるキャンセルは申請中のみ可能とする。
6. 教員専用権限は作らない。
7. 未返却専用画面は作らず、一覧で返却期限超過を表示する。
8. 施設・備品は物理削除せず利用停止で管理する。
9. 予約申請時の利用目的は必須入力とする。
10. 重複成立判定の対象は承認済み・貸出中とする。
11. 承認時に必ず重複チェックを再実行する。
12. SQLインジェクション、XSS、CSRF、Session Fixation、IDOR、エラー情報漏えい対策をMVP必須とする。
13. 重要操作の監査ログをMVPに含める。
14. 重要操作前の再認証は将来候補とする。
15. PHPの詳細エラー表示無効化は今回のMVP必須要件には追加しない。
16. セキュリティヘッダーは `X-Content-Type-Options: nosniff` と `X-Frame-Options: DENY`（または同等CSP）を必須とする。
