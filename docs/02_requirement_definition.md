# 学内施設・備品予約貸出管理システム 要件定義書（初版）

## 1. 概要

### 1.1 目的
現在、紙・口頭・表計算ファイルなどで個別管理されている学内施設・備品の予約・貸出業務をWeb上で一元管理し、予約重複や確認漏れを減らす。

### 1.2 開発対象
授業内で動作確認する学内向けWebシステムとする。一般公開は想定しない。

### 1.3 開発環境
- PHP
- MySQL / MariaDB（XAMPP）
- HTML
- CSS
- JavaScript
- Git / GitHub
- VSCode

### 1.4 開発期間
前半セット第1回〜第7回までに、設計・開発・テスト・発表を行う。

---

## 2. 利用者・権限

### 2.1 一般利用者
一般学生、および予約のみを行う教員を想定する。

できること：
- ログイン / ログアウト
- 施設・備品一覧の閲覧
- 名前・分類による簡易検索
- 施設・備品の詳細確認
- 予約申請
- 自分の予約状況確認
- 申請中の予約キャンセル

できないこと：
- 他利用者の予約情報閲覧
- 施設・備品の管理
- 予約の承認・却下
- 貸出・返却状態の変更

### 2.2 管理担当者
学務課職員、および管理を補助する教員を想定する。

できること：
- 一般利用者向け機能
- 施設・備品の登録・変更・利用停止
- 予約申請一覧の確認
- 予約の承認・却下
- 貸出・返却状態の変更
- 返却期限超過の確認

### 2.3 教員の扱い
教員専用の第三権限は作らない。業務内容に応じて「一般利用者」または「管理担当者」として扱う。

---

## 3. 対象範囲（MVP）

第7回までのMVPは、「施設・備品を探す → 予約申請 → 管理者承認 → 貸出 → 返却 → 状況確認」という基本フローを正しく動作させることを優先する。

MVPに含める：
- ログイン / ログアウト
- 権限制御
- 施設・備品一覧
- 名前・分類による簡易検索
- 施設・備品詳細
- 予約申請
- 予約期間の重複防止
- 管理担当者による承認 / 却下
- 貸出 / 返却状態管理
- 自分の予約状況確認
- 申請中予約のキャンセル
- 施設・備品の利用停止
- 返却期限超過表示

## 6. 状態遷移

### 6.1 予約・貸出状態

```text
申請中
 ├─ 管理担当者が承認 → 承認済み
 ├─ 管理担当者が却下 → 却下
 └─ 一般利用者がキャンセル → キャンセル

承認済み
 └─ 管理担当者が貸出処理 → 貸出中

貸出中
 └─ 管理担当者が返却処理 → 返却済み
```

### 6.2 返却期限超過
「返却期限超過」は独立した予約状態にはせず、以下の条件を満たした場合の表示とする。

```text
状態 = 貸出中
AND
返却予定日 < 現在日
```

## 7. 主要データ

### 7.1 利用者
- 利用者ID
- 氏名
- 学籍番号または職員番号
- メールアドレス
- パスワード
- 権限（一般利用者 / 管理担当者）
- 利用状態

### 7.2 分類
- 分類ID
- 分類名
- 説明

### 7.3 施設・備品
- 対象ID
- 名称
- 分類ID
- 説明
- 保管場所
- 利用状態（利用可能 / 利用停止等）

### 7.4 予約・貸出
MVPでは予約と貸出・返却を別テーブルに分けず、一つの予約データに状態と貸出・返却情報を持たせる案とする。

- 予約ID
- 利用者ID
- 対象ID
- 利用開始日
- 返却予定日
- 利用目的
- 状態
- 貸出日
- 返却日
- 担当者ID
- 備考

※テーブル分割の最終決定は設計工程で行う。

## 8. 業務ルール

1. 予約は時間単位ではなく、「利用開始日〜返却予定日」の日付範囲で管理する。
2. すべての予約は管理担当者による手動承認とする。
3. 予約申請時の「利用目的」は必須入力とする。
4. 一般利用者がキャンセルできるのは「申請中」の予約のみとする。
5. 施設・備品は物理削除せず、「利用停止」として管理する。
6. 利用停止中の施設・備品は新規予約できない。
7. 教員専用権限は設けず、一般利用者または管理担当者として登録する。
8. 返却期限超過は専用状態を追加せず、貸出中かつ返却予定日超過時に表示する。
9. 予約重複は「同一対象」かつ「既存予約の利用期間と新規申請期間が重なる場合」とする。
10. 却下・キャンセル・返却済みの予約を重複判定の対象に含めるかは、設計時に状態ごとの扱いを明確化する。

## 9. システム全体の受入条件

以下をすべて確認できれば、MVPの受入条件を満たすものとする。

1. 一般利用者がログインできる。
2. 一般利用者が施設・備品を一覧・簡易検索から探せる。
3. 一般利用者が利用開始日・返却予定日・利用目的を指定して予約申請できる。
4. 重複する期間の予約申請をシステムが拒否できる。
5. 管理担当者が申請を承認または却下できる。
6. 管理担当者が承認済み予約を貸出中、貸出中を返却済みに変更できる。
7. 一般利用者が自分の予約状態を確認できる。
8. 一般利用者が申請中の予約をキャンセルできる。
9. 一般利用者が管理機能を操作できない。
10. 管理担当者が施設・備品を登録・変更・利用停止できる。
11. 返却予定日を過ぎた貸出中データが「返却期限超過」と分かる。
12. 未入力や不正な入力時に、修正方法が分かるエラーメッセージが表示される。
13. ChromeまたはEdgeで主要機能が正常に動作する。
14. テスト結果と簡単な操作手順を説明できる資料が用意されている。

## 11. 未決事項・要確認

### 要確認1：重複判定に含める予約状態
申請中・承認済み・貸出中のどこまでを「他の利用者が予約できない期間」として扱うか、設計時に最終決定する。

### 要確認2：アカウントの作成方法
利用者アカウントを管理担当者が事前登録するか、初期データとして固定するかは原本に明記されていないため要確認。

### 要確認3：施設と備品の扱い
施設と備品を同一テーブルで扱うか、別テーブルにするかは設計時に決定する。

### 要確認4：却下時の理由
管理担当者が却下理由を入力するかどうかは原本に明記されていないため要確認。

## 13. 今回の合意事項

1. WISH-03は一覧表示をMVP必須とする。
2. WISH-04は名前・分類による簡易検索としてMVPに含める。
3. 予約は利用開始日〜返却予定日の期間指定とし、時間単位は扱わない。
4. すべての予約を管理担当者の手動承認とする。
5. 学生によるキャンセルは申請中のみ可能とする。
6. 教員専用権限は作らず、一般利用者または管理担当者として扱う。
7. 未返却専用画面は作らず、一覧で「返却期限超過」を表示する。
8. 施設・備品は物理削除せず、「利用停止」で管理する。
9. 予約申請時の利用目的は必須入力とする。
